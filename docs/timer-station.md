# 独立计时站

Windows 完整工作台标题栏的“计时站”或工作站标题栏的计时图标打开计时视图。完整工作台、工作站和计时站三者互斥，同一时间只显示一个：打开计时站自动隐藏主窗口和工作站贴边入口，切回任一工作视图自动隐藏计时站。重复打开复用已有计时站。Web/PWA 不增加原生窗口入口。

计时站使用“打开完整工作台”文字入口，点击后返回并聚焦完整工作台；极短窄窗把该入口与排列选择收纳进「更多操作」菜单，仍不提供直达工作站的入口。工作站、贴边收起或完整工作台最小化时均可使用；运行计时、开始时间和尺寸不变。直接关闭计时站会恢复之前隐藏的工作视图；如之前收起为贴边入口，则展开工作站，避免无可见入口。入口复用父窗口桌面状态转换及聚焦能力，不新建业务窗口、不增加子窗口 bridge 权限。原生验收脚本覆盖这些恢复路径、真实窗口可见性和计时缓存一致性。

## 交互与外观

- 暖白背景、衬线字体。项目与任务名称同排，长名称省略并保留完整提示；正计时绿色向上、倒计时红色向下。每张卡片展示账号时区中的“开始于 年/月/日 时:分”；旧计时缺少首次开始时刻时明确显示未记录。
- 横向最多三张独立卡片；纵向堆叠。宽度至少 340 DIP 时标题栏 44 DIP；更窄时通常为 80 DIP 两行布局。宽小于 340 CSS px 且高小于 240 CSS px 的极短窗改为 44px 单行：标题、更多、置顶／最小化／关闭保持可点击，完整工作台和排列位于更多菜单。卡片基准高 144 DIP；三张横排默认 940×208 DIP，三张纵排默认 340×516 DIP。正常尺寸保留项目名、17px 任务名、完整开始时间、醒目的衬线数字与红绿箭头；窄卡优先展示任务名和暂停／完成，计时模式仍可由可访问名称识别。
- 拖动原生边框或角落可调整宽高，最小 200×112 DIP 不变。原生层继续收紧多余高度、记忆横纵首选尺寸、保留置顶与全部窗口命令。正常窗口按实际可用宽高整体适配，缩放范围为基准的约 67%–125%，36px 动作按钮缩放后不小于约 24 CSS px；双卡 500×178 DIP 时仍能完整展示。空间不足以维持该命中区时，不再把整张卡片压到数个像素，而改为原尺寸可滚动卡片区，保留横／纵排列偏好与全部任务。滚动区和每卡操作均可通过 Tab 抵达，暂停／完成保持 36px，窄卡更多入口可直接点击；焦点反馈与全项目方案 A 一致。收放窗口不会改变计时或保存数据。
- 默认置顶，可切换；排列和置顶偏好以 `threadline.timer-station.v1` 保存在本机。标题栏可拖动、最小化和关闭。关闭计时站不停止计时，重开恢复当前状态。
- 暂停、继续、到时续时、完成并记耗时与首页使用相同卡片逻辑；窄于 280 DIP 时续时选项分两列，保持完整可点击。右键或 Shift+F10 提供删除计时器。删除计时器与完成记账是不同操作。
- 点击完成后，先在同账号 Web Lock 内确认本机待提交记录，再立即从首页和计时站收起该卡片并按剩余数量补位，无需等待云端响应。共享父会话继续保存完成状态和耗时，失败时恢复暂停的卡片并显示错误，重试沿用首次提交的分钟、时段和请求 ID。云端确认前，本机保留待保存意图，也继续占用该任务的计时槽位以防重复启动；应用重载后未确认的计时会恢复供核对重试，不会因视觉收起而丢失。暂停、续时和删除也使用相同独占提交，避免另一标签覆盖操作。
- 关闭整个应用、主文档重载、退出账号或更换账号会关闭计时站。已持久化的本机计时保留；新账号只读取其自己的计时缓存。

## 架构与安全

沿用唯一的 `TaskTimersSession`，通过 React portal 把卡片挂到同源子窗口。`threadline-role=timer-station` 在 hydration 后只挂载展示容器，不加载认证、工作区或第二份计时 Provider。父窗口继续拥有时钟、账号和所有保存回调；共享保存 Promise 与原有 CAS 校验避免两处控件重复发起同一保存。

`electron/timer-station.cts` 只准许 Main 打开固定 frameName 与精确同源 URL，拒绝其他弹窗、重定向和任意导航；子窗口继承 sandbox、contextIsolation，关闭 nodeIntegration，不暴露业务 IPC 或 Node。有限窗口命令由 Main bridge 调用，校验所属顶层 frame 和命令字段。父窗口结束时原生子窗口一并销毁。

计时站在用户体验上与工作站同属轻量视图，原生层仍使用同源子窗口，隐藏的 Main 保持唯一计时会话。Main 的统一 reveal、系统 show／restore、贴边入口 reveal 都先隐藏计时站；计时站首次就绪或再次聚焦会隐藏 Main 和 Edge，并取消迟到的窗口切换。计时站激活时显示器恢复由其独立几何模块处理，不唤醒隐藏工作视图。返回工作视图不销毁子窗口，后台配置不会重新显示它；关闭／账号卸载／主文档重载仍按生命周期清理。

原生窗口单独隔离缩放，显示器移除或工作区变化时恢复到可见范围。计时站打开期间关闭父会话的后台节流，保证工作站隐藏或主窗口最小化后继续刷新；关闭计时站恢复原节流设置。弹出菜单使用触发器的 ownerDocument 定位、渲染、处理焦点，保证续时浮层实际位于计时站中。

`use-timer-station-fit.ts` 在子窗口中观察卡片视口和内容高度，以完整横排／纵排的基准尺寸计算比例。比例低于三分之二时，视口与卡片切换到 `data-fit="scroll"`，停止 transform 缩放并使用可滚动网格；动态卡宽有 CSS 默认值，不依赖未定义令牌。标题栏和独立 portal 浮层始终保持正常交互，错误提示增高也会重新测量。卡片明确指定标题、读数／按钮、开始时间的网格行，隔离共享卡片的手机断点。

测量先判定理论上限，再按需要读取卡片内容高度，最后发布视口的最终适配模式。始终只能滚动的小窗重复测量时不会短暂宣告 `scale`，避免外部把滚动布局按缩放布局读取；对应 MutationObserver 单测保留先红后绿的回归。

`electron/timer-station-geometry.cts` 负责原生尺寸：按 Electron 的 `will-resize`／`resized` 事件区分用户拖动与程序调整，沿用 300×144 横排／320×144 纵排基准、125% 放大上限和宽窗 44／窄窗 80 DIP 标题栏预算收掉多余高度，原子替换 userData 中的 `timer-station-sizes.json`。极短窄窗的渲染器可以将标题栏收纳为 44px，并用滚动区维持控制目标；不改变原生最小尺寸或用户已存尺寸。尺寸文件只存两种排列的宽高，损坏时回退默认值；工作区恢复不覆盖首选尺寸。配置更新不唤醒已经最小化的窗口。

选用 Electron 官方支持的[同源父窗口直接渲染子窗口](https://www.electronjs.org/docs/latest/api/window-open)机制；没有新增云表、迁移或计时副本。原始时间与历史沿用[计时统计规则](timer-accounting.md)，统计仍总量去重、分布均分。

## 验证与本地预览

在 PowerShell 中构建显式测试适配器与原生壳，然后运行隔离窗口验收：

```powershell
$env:NEXT_PUBLIC_THREADLINE_TEST_ADAPTER='true'
pnpm desktop:renderer
pnpm desktop:compile
node scripts/test-electron-timer-station.mjs
```

脚本用独立临时 userData、真实 `threadline://app/` 静态资源与 CSP 验证一至三张卡片、横纵排列、正常窗口的全部边界与底部余量，以及极小窗口逐卡滚动后的真实命中区和暂停／继续点击。还覆盖 100%、125%、150%、250% 的真实 webContents 缩放，最小 200×112 DIP 三卡键盘到达、更多菜单关闭和焦点归还；实际按钮尺寸保存到 `hig-station-zoom-targets.json`。原有计时同步、开始时间、置顶、关闭重开、续时、单次记账、视图互斥、贴边入口和重载恢复均继续检查。原生尺寸、排列记忆和多卡 500×178 DIP 流程保持；程序设置真实窗口并模拟拖动起止事件不等于物理鼠标拖动验收。截图位于 `test-results/timer-station/`，包括 `minimum-reachable-controls.png`、`two-timers-small.png` 和 `horizontal-smallest.png`。

2026-11-19 方案 A 原生复验：完整脚本通过。四档缩放使用工作区内的 1000×600 DIP 请求尺寸（屏幕更小时按实际工作区夹紧），逐档记录实际尺寸、原生 bounds、workArea、可见／最小化状态及按钮矩形，并在实际点击后再次确认窗口仍原生可见。按钮最小边均至少约 24 CSS px；最小 200×112 DIP 三卡采用原尺寸滚动控件，暂停／完成均为 36px。首轮夹具曾强设超过物理工作区的窗口，同时出现了屏外点击风险和最小化干扰；已改为屏内定位与包含性断言，未放宽尺寸、命中或可见性标准。另修正了 resize 后适配模式尚未更新时，脚本提前按旧模式验证的等待竞态。复跑还记录过额外的「最小化计时站」DOM 点击；最终串行独占输入的完整原生运行通过，额外输入来源未做唯一归因，后续同机原生回归应串行以免干扰判定。以上是隔离真实 Electron 验证，不是生产安装包或实体触摸硬件验收。

同日 PR CI 的 Windows 最小窗验收曾在已确认 `scroll` 后进入缩放布局的底部余量检查。本机原脚本及 12 轮窗口收放未复现该失败，但 MutationObserver 确认旧测量流程会短暂发布中间 `scale`。修正最终模式发布后，两项回归先红后绿；真实 200／201 DIP 小宽度的四轮收放只记录到 `scroll`，原几何、命中与暂停／继续检查保持不变。随后完整 `pnpm test:electron` 从编译、启动、双屏登录入口、静态 Renderer、计时站、Web 构建到窗口 smoke 全部通过；未放宽原断言或阈值。本机通过不代替 PR CI 或安装版验收，也不为 CI 的历史失败做唯一原因断言。

追加 `--show` 可保留三条示例任务的本地预览窗口；这些是隔离演示数据，不是实际账号记录。脚本不生成安装包，不访问真实账号。真实账号的网络失败和多屏物理拔插仍需上线前另验。

## 窄窗适配依据

遵循 [Microsoft 响应式布局](https://learn.microsoft.com/en-us/windows/apps/design/layout/responsive-design)的重排方式，标题栏在空间不足时分行；使用 [CSS 媒体查询](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries)选择布局，保留 [ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver)对卡片可用空间的观察。原生最小宽度通过 [Electron setMinimumSize](https://www.electronjs.org/docs/latest/api/base-window#winsetminimumsizewidth-height)统一设置为 200 DIP，并同步放宽持久化校验；340 DIP 只作为标题栏断点和默认纵排宽度。系统 DPI 缩放只改变物理像素换算，不再额外使用页面 zoom 放大标题栏或伪造窗口缩放。
