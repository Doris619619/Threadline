# 独立计时站

Windows 完整工作台标题栏的“计时站”或工作站标题栏的计时图标打开计时视图。完整工作台、工作站和计时站三者互斥，同一时间只显示一个：打开计时站自动隐藏主窗口和工作站贴边入口，切回任一工作视图自动隐藏计时站。重复打开复用已有计时站。Web/PWA 不增加原生窗口入口。

计时站标题栏只保留“打开完整工作台”文字按钮，点击后返回并聚焦完整工作台；不提供直达工作站的入口，工作站从完整工作台进入。工作站、贴边收起或完整工作台最小化时均可使用；运行计时、开始时间和尺寸不变。直接关闭计时站会恢复之前隐藏的工作视图；如之前收起为贴边入口，则展开工作站，避免无可见入口。入口复用父窗口桌面状态转换及聚焦能力，不新建业务窗口、不增加子窗口 bridge 权限。原生验收脚本覆盖这些恢复路径、真实窗口可见性和计时缓存一致性。

## 交互与外观

- 暖白背景、衬线字体。项目与任务名称同排，长名称省略并保留完整提示；正计时绿色向上、倒计时红色向下。每张卡片展示账号时区中的“开始于 年/月/日 时:分”；旧计时缺少首次开始时刻时明确显示未记录。
- 横向最多三张独立卡片；纵向堆叠。宽度至少 340 DIP 时标题栏 44 DIP；更窄时为 80 DIP 两行布局，第一行保留标题和置顶／最小化／关闭，第二行保留完整工作台文字入口与横纵切换。卡片基准高 144 DIP；三张横排默认 940×208 DIP，三张纵排默认 340×516 DIP。辅助项目名和完整开始时间采用 12px 系统字体，任务名 17px；保留醒目的衬线计时数字、红绿与箭头。
- 拖动原生边框或角落可调整宽高，通常最小 200×112 DIP。松开边框后，按当前宽度、排列和卡片数量收紧窗口高度，底部只留约 10 DIP 边距；可继续手动压低高度，卡片随可用空间缩放。双卡横排缩至 500 DIP 宽时，高度约 178 DIP。横纵尺寸分别记忆，关闭重开和应用重启仍恢复；置顶不改变尺寸；任务数量变化可收掉新增空白，但不覆盖保存的首选尺寸。尚未自定义时按数量调整默认大小。卡片区域按实际可用宽高整体适配，卡片、数字、按钮和开始时间同步缩小，所有计时器保持可见，不用横纵滚动浏览。标题栏控件保持原尺寸、窄窗重排，避免整体缩小按钮。放大上限为基准的 125%，避免无限拉大；数字与暂停／完成按钮始终同排，计时站不应用首页的手机换行规则。
- 默认置顶，可切换；排列和置顶偏好以 `threadline.timer-station.v1` 保存在本机。标题栏可拖动、最小化和关闭。关闭计时站不停止计时，重开恢复当前状态。
- 暂停、继续、到时续时、完成并记耗时与首页使用相同卡片逻辑；右键或 Shift+F10 提供删除计时器。删除计时器与完成记账是不同操作。
- 关闭整个应用、主文档重载、退出账号或更换账号会关闭计时站。已持久化的本机计时保留；新账号只读取其自己的计时缓存。

## 架构与安全

沿用唯一的 `TaskTimersSession`，通过 React portal 把卡片挂到同源子窗口。`threadline-role=timer-station` 在 hydration 后只挂载展示容器，不加载认证、工作区或第二份计时 Provider。父窗口继续拥有时钟、账号和所有保存回调；共享保存 Promise 与原有 CAS 校验避免两处控件重复发起同一保存。

`electron/timer-station.cts` 只准许 Main 打开固定 frameName 与精确同源 URL，拒绝其他弹窗、重定向和任意导航；子窗口继承 sandbox、contextIsolation，关闭 nodeIntegration，不暴露业务 IPC 或 Node。有限窗口命令由 Main bridge 调用，校验所属顶层 frame 和命令字段。父窗口结束时原生子窗口一并销毁。

计时站在用户体验上与工作站同属轻量视图，原生层仍使用同源子窗口，隐藏的 Main 保持唯一计时会话。Main 的统一 reveal、系统 show／restore、贴边入口 reveal 都先隐藏计时站；计时站首次就绪或再次聚焦会隐藏 Main 和 Edge，并取消迟到的窗口切换。计时站激活时显示器恢复由其独立几何模块处理，不唤醒隐藏工作视图。返回工作视图不销毁子窗口，后台配置不会重新显示它；关闭／账号卸载／主文档重载仍按生命周期清理。

原生窗口单独隔离缩放，显示器移除或工作区变化时恢复到可见范围。计时站打开期间关闭父会话的后台节流，保证工作站隐藏或主窗口最小化后继续刷新；关闭计时站恢复原节流设置。弹出菜单使用触发器的 ownerDocument 定位、渲染、处理焦点，保证续时浮层实际位于计时站中。

`use-timer-station-fit.ts` 在子窗口中观察卡片视口和内容高度，以完整横排／纵排的基准尺寸计算统一比例。缩放只作用于展示网格，标题栏和独立 portal 浮层保持正常交互；错误提示增高也会重新测量。卡片明确指定标题、读数／按钮、开始时间的网格行，隔离共享卡片的移动端断点。

`electron/timer-station-geometry.cts` 负责原生尺寸：按 Electron 的 `will-resize`／`resized` 事件区分用户拖动与程序调整，拖动结束先按与渲染器一致的 300×144 横排／320×144 纵排基准和 125% 缩放上限收掉多余高度，并计入宽窗 44／窄窗 80 DIP 标题栏，再读取内容逻辑尺寸，原子替换 userData 中的 `timer-station-sizes.json`。该文件只存两种排列的宽高，损坏时回退默认值；工作区恢复不覆盖首选尺寸。配置更新不唤醒已经最小化的窗口。

选用 Electron 官方支持的[同源父窗口直接渲染子窗口](https://www.electronjs.org/docs/latest/api/window-open)机制；没有新增云表、迁移或计时副本。原始时间与历史沿用[计时统计规则](timer-accounting.md)，统计仍总量去重、分布均分。

## 验证与本地预览

在 PowerShell 中构建显式测试适配器与原生壳，然后运行隔离窗口验收：

```powershell
$env:NEXT_PUBLIC_THREADLINE_TEST_ADAPTER='true'
pnpm desktop:renderer
pnpm desktop:compile
node scripts/test-electron-timer-station.mjs
```

脚本用独立临时 userData、真实 `threadline://app/` 静态资源与 CSP 验证一至三张卡片、横纵排列、窄／宽窗口内所有卡片边界和开始时间完整可见、数字与按钮同排、双向暂停／继续同步、开始时间不变、置顶、关闭重开、子窗口内续时、单次完成记录、三个视图互斥、贴边入口隐藏与父文档重载清理。另覆盖原生最小宽度确为 200 DIP（程序设置尺寸可绕过该限制，需单独核查）、200／240 DIP 纵排、339／340 DIP 断点、窄窗标题栏全部控件无覆盖及可操作，以及用户报告的 500×208 DIP 双卡横排自动收紧至 500×178 DIP、卡片底部边距、低于旧最小高度的尺寸恢复和缩放后的按钮点击。尺寸测试检查原生 resizable 状态，程序改变真实窗口并模拟拖动起止事件，验证横纵独立记忆、置顶／数量变化不覆盖首选尺寸和整个应用重启恢复；它不代替物理鼠标拖动验收。截图位于 `test-results/timer-station/`，包含 `two-timers-small.png` 和 `horizontal-smallest.png`。

追加 `--show` 可保留三条示例任务的本地预览窗口；这些是隔离演示数据，不是实际账号记录。脚本不生成安装包，不访问真实账号。真实账号的网络失败和多屏物理拔插仍需上线前另验。

## 窄窗适配依据

遵循 [Microsoft 响应式布局](https://learn.microsoft.com/en-us/windows/apps/design/layout/responsive-design)的重排方式，标题栏在空间不足时分行；使用 [CSS 媒体查询](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Media_queries)选择布局，保留 [ResizeObserver](https://developer.mozilla.org/en-US/docs/Web/API/ResizeObserver)对卡片可用空间的观察。原生最小宽度通过 [Electron setMinimumSize](https://www.electronjs.org/docs/latest/api/base-window#winsetminimumsizewidth-height)统一设置为 200 DIP，并同步放宽持久化校验；340 DIP 只作为标题栏断点和默认纵排宽度。系统 DPI 缩放只改变物理像素换算，不再额外使用页面 zoom 放大标题栏或伪造窗口缩放。
