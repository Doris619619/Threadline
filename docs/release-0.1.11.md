# Threadline 0.1.11

- 「规划」改为「日历」，「项目」改为「计划」。计划页按阶段计划、项目、Daily 排列，使用当前主题的响应式卡片，各区域有独立创建入口。
- 阶段清单先收集任务，再安排到日期。首页完整展示所有开启显示且未结束的阶段；安排、完成和取消完成仍操作同一个 Task，结束后的阶段永久保留回顾。
- 项目卡片进入该项目的全部任务，支持状态筛选和搜索。阶段任务仍属于原项目，默认「其他」，创建及追加均能选择项目。
- 创建阶段支持 Enter 连续添加、逐项项目下拉和失败保留；手机采用两步短表单。首页任务行的项目与标题并排，复选框和首行对齐。
- 合并前审计修复两处并发问题：旧阶段草稿不会使用实时更新后的新版令牌覆盖其他设备的修改；迟到的确认回包不会将缓存退回较旧版本，也不会重现已删除阶段或恢复其任务归属。

## 数据库与发布顺序

先依次应用 `202610010001_stage_plans.sql`、`202610010002_stage_task_projects.sql`，核对 RLS、同账号外键、RPC 权限、Realtime 和历史保留，再合并客户端并推送 `v0.1.11`。

新增阶段表与任务的阶段关联列；不复制任务。删除阶段只清除归属，保留任务、日程、项目及耗时账本。仍有关联的阶段回收站任务免于普通 30 天物理清理。多端建议一起更新，旧客户端不了解阶段待安排隔离。

Windows 安装包由正式 tag 流水线执行 Preview/package parity、生产配置构建和资产校验后公开，包含安装器、blockmap 与 `latest.yml`。客户端继续采用原来的用户确认更新流程。

## 验证边界

并发问题已通过先失败、修复后通过的组件回归确认。浏览器额外核对首页任务的首行对齐、项目并排、长标题与手机布局。Linux WebKit CI trace 显示冷启动能超过原先 10 秒等待但最终成功，首屏等待改为 30 秒；保存与数据断言继续保持原标准。

完整验证结果及截图见 [阶段计划说明](stage-plans.md) 和 PR #52。自动化不替代实体 iPhone 键盘/PWA 或用户设备上的 Windows 安装升级体验。
