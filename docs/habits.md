# 习惯

实施基线：2026-09-12 核实的远端 `main`，`ecf6f6c61205c0e554894a2885f03d938592c2ed`。分支 `feat/20260912-habits`。

## 记录与查看

2026-09-12 布局修订：三行打卡采用对齐与细分隔线；周/月共用工具栏，睡觉与起床趋势宽屏并排；作息规律、历史与补录可展开。研究来源和实现边界见 [习惯布局与账号时区](habits-layout-timezone.md)。

一级栏目按今天打卡、周/月统计、睡觉/起床趋势、工作效率、规律、历史排列。手机直接显示习惯，洞察移到更多；Electron 完整窗口提供本页，工作站和 Edge 保留原界面。

起床了/睡觉了立即捕获真实瞬间并显示保存中，不弹档位选择器。已记录的 HH:mm 时间本身就是编辑入口，打开时直接聚焦该项时间。凌晨显示 01:10，不在数值前添加“次日”；归属日期在必要时另行说明。好/中/差表示当天工作效率，点选即保存。失败保留点击时间、草稿和请求 ID；手动重试不重新计时。另一项打卡不能覆盖待重试输入，用户可显式丢弃输入并重新读取服务端状态。没有离线写队列。历史详情支持逐项补录、改归属、清除、恢复最近一次值；多项同次保存原子提交。

周一为周起点；周/月统计范围与顶部当前打卡独立。图表漏记断开、目标按历史规则变化，提供准确日期数值按钮作为键盘替代。状态按类别展示，不计算情绪或效率平均分。历史月历切换睡觉、起床、效率。

## 时区、分日与目标

账号首次登录初始化时以设备 IANA 时区提供默认值，已有选择优先；“设置 → 日期与时区”和习惯设置共用同一账号真源。整个 App 的今天、日期归属、历史时间戳展示和规划时间线均按所选时区运行。页头显示该时区的月日、星期、实时时钟和地区名称。修改时区立即作用于新记录，历史保留记录时区。起床使用发生时刻自然日期；睡觉和效率在 00:00–03:59 归前一天，04:00 起归当天。页面每秒和恢复前台时更新日期，正在保存的请求使用冻结时间。04:00 后异常作息可在历史中显式改归属；睡觉实际日期允许当天或次日，起床只允许当天。

| 项目     | 默认分钟规则             |
| -------- | ------------------------ |
| 起床     | ≤06:50 达标              |
| 睡觉达标 | ≤23:20                   |
| 稍晚     | >23:20 且 <次日00:00     |
| 较晚     | ≥次日00:00 且 ≤次日00:30 |
| 很晚     | >次日00:30               |

四档名称固定。起床目标、睡觉达标上限、较晚起点、较晚上限分别编辑，三个睡觉边界须在当天04:00至次日04:00之前严格递增。修改从下一业务日期生效；同一生效日期多次修改使用最后版本。历史补录按目标日期规则，启用前日期用初始规则；修改归属重新选规则。原始秒和毫秒保留，显示与分档按分钟。Temporal 显式处理夏令时：缺失时刻拒绝，重复时刻要求选择第一次或第二次。

## 统计口径

达标率按该项有效记录计算，显示达标/已记录，缺失不补零，无数据为 —。未来日期排除；已有当前记录纳入。睡觉分钟相对业务日期连续计算，23:50 与次日00:20 的平均为次日00:05；起床使用自然日分钟。混合时区按每条记录的墙钟统计并提示。好/中/差单独计数。

规律比较最近14个完整业务日与此前14日，各项两段都至少7次记录才给提前/推迟/持平结论，同时显示样本和日期范围，不生成健康或因果建议。

## 数据和同步

- `habit_settings`：每账号一份时区、设置版本和配置请求去重标识。
- `habit_rule_versions`：只追加的目标与三个分界、生效业务日期。
- `habit_entries`：账号、业务日期、类型、原始瞬间、本地时间/时区、效率、规则、来源、版本、软删除及审计时间；同账号日期类型最多一条有效记录。
- `habit_entry_revisions`：每次首次记录、修改、清除和恢复的完整快照及稳定请求标识；原始值不覆盖。

RLS 只允许本人读取。客户端没有直接表写权限；`apply_habit_entries`（1–3项原子操作）和 `configure_habits` 是受控 SECURITY DEFINER RPC，固定 search_path，从 auth.uid() 取账号，以账号 advisory lock 序列化事务。时间自动打卡首次优先；编辑需 expected_version；旧请求重试返回当前记录，避免回滚较新版本。记录和规则用账号复合外键限制跨账号引用。

`HabitsStateProvider` 复用云端 React Query，查询键含账号和范围，进入习惯时才查询；全局 AccountTimezoneProvider 先确认账号时区再挂载业务树，防止首次点击使用电脑日期；只有时区设置参与此读取，不预加载习惯历史。时区订阅独立于习惯范围查询，账号设置写入立即使用服务器返回值更新时钟，较旧读取不得覆盖已确认版本；Realtime 刷新对应表。确认结果按版本单调合并，待保存意图独立于查询。失败刷新不撤销已保存数据。账号切换拆除旧 Store 和订阅，迟到写响应不注入缓存。保存接入桌面 cloud-write guard。

Preview/测试采用相同接口及纯事务校验，使用独立 `threadline.test.habits.v1` 命名空间（Preview 经 workspaceStorageKey 隔离）。Web Locks 序列化同源标签页操作；不具备 Web Locks 的旧浏览器只保证单标签同步事务。正式云端失败不会退回本地存储。

## 上线与验证边界

迁移 `202609120001_habits.sql` 只新增四张表、索引、权限和函数，不回填或重算任务、Daily、收尾记录。先核对实际待迁移列表和 dry-run，再部署数据库，最后发布客户端；旧客户端兼容。回退客户端时保留习惯表和已产生记录。

首轮实施按用户要求不启动本地数据库，不执行数据库、真实云端双账号/双设备验收，也没有部署生产迁移。SQL 静态检查只能验证结构文本，不能代替 PostgreSQL 执行。`supabase/tests/habits.test.sql` 保留权限、幂等、归日、版本与修订测试供后续环境执行。上线前仍需验证实际迁移、RPC、RLS、并发首次打卡与跨设备冲突。

定向检查：`pnpm exec vitest run tests/habit-*.test.*`；`pnpm test:sql:static`；`pnpm test:e2e habits.spec.ts --project=desktop --project=mobile --project=planning-webkit`。完整验收记录见 [测试架构](testing-architecture.md)。传感器检测、睡眠时长、提醒、健康评分、效率因果分析、自定义其他习惯与通用离线同步不属于 V1。
