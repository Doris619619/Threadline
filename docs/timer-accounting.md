# 并行计时统计

新计时保存后采用“总量去重、分布均分”。三个任务分别在 14:00、14:30、15:00 开始，15:30 结束：原始分钟为 90、60、30；统计总量为 90，分配分钟为 55、25、10。先按账号全部时段分配，再筛日期、项目和阶段；筛选不会重新分配其他任务的份额。

## 计时与保存

- 正计时和倒计时按真实时间运行，任务编辑保留累计原始分钟。开始、暂停、恢复和续时保存连续运行区间，暂停与到时等待不计入。
- 同账号、同源标签页通过 Web Locks 串行执行整组计时器的读取、容量/旧值校验与保存。暂停不同卡片、续时、删除和新增不会彼此覆盖；普通界面偏好仍沿用同步本机保存。客户端需安全来源及支持 Web Locks 的当前浏览器；缺少锁或本机写入失败会明确报错，不能继续当作已保存。
- 完成前先确认本机待提交记录已经保存，再收起卡片并请求云端。保存中刷新仍保留同一会话 ID、分钟和时段；云端成功后的本机清理若失败，也恢复卡片供幂等重试。
- 倒计时到时后若系统绝对时间回拨，续时锚点不会早于上一运行段终点，追上锚点前不增加耗时，不生成重叠区间。首次开始时间与启动记账日保持不变；时间来源仍是客户端墙钟。
- 沿用“完成并记耗时”提交边界：未保存会话留在本机，不提前写统计。另一重叠任务稍后保存时重新计算分配，最终结果不依赖提交顺序。删除未保存计时器仍不记账。
- 会话 ID 是幂等键，相同请求重试不重复累计。完成、原始账本和时段同事务保存。同任务在不同设备记录的独立会话以增量追加原始分钟，统计时同任务只占一份。
- 新统计按启动时账号时区拆分自然日及夏令时；原始账本继续沿用启动记账日。客户端时钟仍是时段来源，没有新增服务器校时。
- 计算保留小数分钟，界面最终按分钟显示；不足半分钟显示不足一分钟。逐项展示舍入后可能与总数差一分钟，统计不累加这些展示值。

## 原始记录与历史

`tasks.actual_duration_minutes` 和 `task_time_entries` 保留原始分钟，不写回分配值。`task_timer_records` 保存时段、时区、原始分钟、固定任务身份及项目/账本引用；任务物理清理后两套历史仍保留。

旧计时器、历史账本、手动补录和 Daily 无完整时段，原值计入、无法去重。规则保留在本文档中，时间图、洞察和打印报告只展示统计结果，不重复显示整段核算说明。分钟编辑只能减少额外补录余额，不能抹掉已保存计时；本次不提供修改已保存时段的入口。

旧收尾快照不回填。新关账使用分配投影并标记统计版本，不再用其差额补回统计。项目快照只汇总任务，Daily 沿用独立统计，不把无项目 Daily 写成空项目键。旧快照按原始账本核销已覆盖量，其余无法定位到任务的历史投入继续保留，避免重复分钟复活或丢失旧记录。

## 架构与上线边界

Web/PWA 与 Electron 静态前端继续共用客户端业务层，无新增 Next.js 服务端依赖。`timer-rules.ts` 维护本机会话，`timer-accounting.ts` 提供 Preview 分配算法；生产使用 `task_time_statistics` 的账号级统计投影，原始分钟由独立字段核对。

`202610160001_timer_overlap_accounting.sql` 新增只读会话表、RLS、原子 RPC、原始分钟保护及 `security_invoker` 视图。新会话 Realtime 事件刷新当前账号统计，进行中计时仍不跨设备接管。未来上线先应用迁移、再发布客户端；缺少迁移明确失败，不回退到重复相加。

`202610210001_timer_midnight_dst.sql` 以向前迁移替换统计投影：重复午夜选择当天第一次有效瞬间；午夜被跳过或整日不存在时使用真实日界。保留视图列、账号隔离、原始记录与关账依赖，不修改历史迁移或原始账本。已有时段会通过新投影重新统计；此迁移必须在生产单独应用，本地数据库测试不代表已上线。

0.1.15 发布前先通过数据库/API 与客户端门禁，再部署上述迁移、合并已审计源码并发布匹配版本标签。安装包与迁移完成证据记录在[0.1.15 发布说明](release-0.1.15.md)。
