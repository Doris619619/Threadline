# Windows 自动更新

从 0.1.1 起，正式 NSIS 安装版在启动 30 秒后检查新版，持续运行每 6 小时再次检查。设置 → 关于 Threadline 可以手动检查。发现更新只提示，点击后下载并显示真实进度；下载完成后用户确认重启才安装，普通退出不安装。失败保留当前程序，可以重试。

旧 0.1.0 没有更新逻辑，必须手动安装一次新版本。使用同一 appId、应用名称和 userData，保留已有登录与设备偏好。Web/PWA 不提供这个入口；目录 Preview 没有 NSIS 安装标记，只提示使用安装版。测试标记或更新配置不得手工写入交付目录包。

## 发布与配置

源码仍在私有 `Doris619619/Threadline`。公开 `Doris619619/Threadline-releases` 只包含下载说明、NSIS 安装包、blockmap 和 latest.yml。客户端匿名读取公开更新源，不包含 GitHub token 或 Supabase 管理员密钥。

源码仓库 Actions 需配置：

| 名称                                 | 类型     | 内容                                           |
| ------------------------------------ | -------- | ---------------------------------------------- |
| NEXT_PUBLIC_SUPABASE_URL             | Variable | 正式项目公开 URL                               |
| NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY | Variable | 正式项目 sb_publishable_ key                   |
| THREADLINE_RELEASE_TOKEN             | Secret   | fine-grained PAT，仅分发仓库 Contents 读写权限 |

跨仓库 token 由仓库所有者创建并配置，不能把源码仓库默认 GITHUB_TOKEN 或本机广泛权限的登录 token 复制进去。token 失效时发布失败，既有安装不受影响。

每次发布：

1. 修改 package.json 版本并完成 PR 审查与合并。版本必须递增，不覆盖已公开 Release。
2. 在要发布的提交创建匹配的 vX.Y.Z tag 并推送。手动 workflow 同样必须选择版本 tag。
3. Release workflow 校验版本，运行测试和 parity，使用正式 Supabase 公开配置构建；`desktop:release` 仅允许匹配 tag 的 GitHub Actions 执行。
4. 安装包完成本地验证后上传同一个草稿 Release，再下载比较三个资产，全部匹配才公开。失败保留草稿；修复后可重跑同 tag，已经公开则必须递增版本。

本地 `pnpm desktop:build` 和 Preview 均不上传文件。未公开的草稿不会被同学的客户端收到。需要修复坏版本时发布更高版本，客户端不自动降级。

## 实现边界

Main 管理更新状态和并发，Preload 仅向可信主窗口暴露读取、检查、下载、安装与订阅，不接受任意下载地址。状态带单调 revision，防止迟到读取覆盖下载进度。安装时保留正常 app.quit 生命周期，不能直接 app.exit 截断更新器。

云端非 GET/HEAD 请求以及任务队列计入保存保护。更新重启锁在用户点击确认时获取，有保存时拒绝安装；取消或安装失败后释放。锁期间不启动新云写入。此保护不自动提交尚未点击保存的表单，确认框会提示先完成编辑。

## 验收记录

单元/界面测试、真实安装升级和线上更新源验证分别记录在 PR；只有用两个已安装版本走通下载和重启，才标记真实升级通过。新仓库尚无正式 Release 时，检查会显示可重试的网络/更新错误，不能据此声称线上更新已生效。

## 用户验收步骤

1. 运行 `Threadline_0.1.1_x64-setup.exe` 安装，使用安装后的快捷方式打开；不要使用 Preview 目录包。已有安装选择原目录，不卸载或清理数据。
2. 在设置 → 关于确认版本为 0.1.1；检查原登录状态、任务、项目仍在，修改一条可恢复的任务并等待保存完成。
3. 在设置 → 外观依次点击浅色、深色、跟随系统，再分别选择蓝色和安妮雅；手动模式应立即生效且不被系统覆盖。退出重开后选择仍保留。
4. 首次 0.1.1 正式发布后，安装版点击检查更新应显示已是最新版本。断网检查应出现可重试错误，联网后能恢复。
5. 完整升级需要公开更新源存在比当前安装版更高的正式版本（例如后续 0.1.2）。届时在 0.1.1 内检查，应只提示新版，不自动下载。
6. 点击下载更新，观察进度；下载完成先正常退出并重新打开，版本应仍为 0.1.1。再次检查和下载可复用缓存，点击重启并更新后先选稍后，程序应继续可用。
7. 完成当前编辑并等待保存，确认重启并更新。新版应自动打开，在关于中确认版本已升高，登录、数据、明暗模式及字体偏好仍保留。

没有更高正式版本时只能完成前四步，不能把“已是最新版本”当作完整升级通过。若更新安装未完成，记录关于页状态与报错；当前版本应继续可用，也可手动运行官方新版安装包修复。

## 明暗外观

设置 → 外观提供浅色、深色和跟随系统按钮，与蓝色 / 安妮雅配色独立保存。旧设置默认跟随系统，手动选择不受系统明暗变化影响。偏好仅保存在当前设备。
