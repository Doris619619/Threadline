# 任务规划

规划取代旧项目投入月历，内部导航仍为 `calendar`。首页负责当日执行；规划的日期是独立页面状态，默认本地今天，浏览不会更改首页日期。

## 页面行为

- 手机与桌面默认进入月历首页，点击任意日期进入独立的当天详情视图，详情内保留周一开头的周条。用“返回月历”回到来源月份，焦点回到原日期格；跨月补位日期同样适用。页面切换由组件状态管理，不创建独立 URL 或浏览器历史记录。
- 桌面采用完整月历或连续单列详情，取消高低不齐的左右分栏。月历底部待安排入口进入今天详情并展开、定位待安排池；返回后恢复该入口焦点。
- 月历仅统计 active 普通任务，包含完成项，排除待安排、放弃、回收站和 Daily。零项日期只显示日期；非零日期显示小号“x 项”，数量不截断。四档非零热力为 1–2、3–4、5–7、8+，只表示安排密度，不代表任务时长。
- 用户选择雾蓝配色：浅色热力从 `#edf3fa` 到 `#a7c5e5`，深色从 `#232f40` 到 `#3b638e`。日期默认 17px，数量 0.6875rem（默认 11px）、常规字重；小字用独立颜色保持对比。今天用实心圆标记，所选日期用细描边；周条只用小圆点提示有安排，完整数量由可访问名称提供。
- 手机月格高度随可用屏幕高度收紧，保留完整可点击格与小字间距；窄屏、横屏和放大文字允许页面自然滚动。
- 清单按有时间、未定时间、已完成分组。有时间按开始时间升序；已完成默认折叠。预计只累计未完成任务，缺少估时单独标记。
- 新建固定使用打开表单时的浏览日期；过去日期可查看和编辑已有任务，但不提供新增、安排目标。任务可编辑、完成、改期或退回待安排。
- 待安排保留重要/普通分组，显式按钮显示目标日期；提交中防重复，失败保留原数据并显示错误。编辑、改期使用共用可访问模态组件；月历与详情之间不再使用弹窗。

## 设计参考

参考 [Apple 日历月视图](https://support.apple.com/guide/iphone/change-how-you-view-events-iphfd1054569/26/ios/26) 的月/日信息层级，以及 [Fantastical 的月份浏览](https://flexibits.com/fantastical-ios/help/calendar-views) 对日期定位和密度的区分。最终视觉按用户确认保留数量与同色相热力，使用雾蓝方案，并把数量降低为次要文字；没有照搬产品界面或引入其他配色开关。

## 持久化与兼容

普通字段使用新增 `saveTaskConfirmed(task)` 命令，首页与规划共用任务编辑时均等待数据库确认后更新缓存、关闭弹窗；失败保留草稿并允许重试，任务表单继续复用现有校验。初始焦点统一交由模态组件管理，避免输入框提前自动聚焦导致关闭后丢失入口。安排、改期、退回使用原子 `transition_task`。

迁移 `202609060001_task_planning.sql` 新增四参数 RPC：`p_task_id`、`p_transition`、`p_target_date`、`p_time_zone`。客户端传运行设备的 IANA 时区；数据库据此校验目标不早于今天。改期允许提前或推后，拒绝原日期及已完成任务；历史保留 from/to 日期，实际投入仍在原账本日期。三参数入口保持可调用，按 UTC 校验。

此迁移只替换函数、设置新重载权限，不执行历史数据更新或清理。应先部署迁移再发布新客户端；部署状态与本地验证分开报告。

本期不提供 Daily 未来展开、小时刻度、拖拽排程或外部日历同步。原 analytics 仍供洞察和报告使用。
