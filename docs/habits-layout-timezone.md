# 习惯布局与账号时区

## 界面依据

本次按官方界面与指南选择具体交互，未登录付费产品账号实测。

- [Things](https://culturedcode.com/things/)：借鉴紧凑列表中一致的对齐、分组留白和就地操作。今天的三项以细分隔线区分，已记录时间直接点击编辑，去掉额外“修改”按钮。
- [Apple Health](https://support.apple.com/en-au/guide/iphone/iph72b370881/ios)：借鉴统一时间范围以及点日查看详情。周/月工具栏控制全部统计；历史保留独立月历，但默认收起，避免同时展示两份日期网格。
- [Oura Trends](https://support.ouraring.com/hc/en-us/articles/360055983614-Using-Trends)：借鉴平均值与趋势图放在一起、具体数值按需查看。保留独立睡觉/起床图、目标线和键盘可用的数值列表。
- [Streaks](https://streaksapp.com/)：借鉴快速完成与记录结果原位反馈。效率仍为好/中/差单击保存，不引入情绪评分。

时钟集中显示所选地区的月日、星期与 24 小时制秒钟；时间数据用等宽数字。重复日期、未记录占位、大面积有边框卡片被移除。跨午夜归属日期仍在睡觉行说明。手机保留至少 44px 触控区域，输入至少 16px。

## 统一日期边界

`habit_settings.timezone` 提升为账号唯一时区真源，兼容 0.1.5 的设置写入。`AccountTimezoneProvider` 在已登录账号边界读取并确认设置，再挂载业务树；未设置账号通过受控 RPC 初始化。客户端时钟状态只存在当前浏览器/窗口会话，退出或换号清除，服务端不写入该状态。

`getLocalDateKey(instant)`、历史时间戳映射、任务改期 RPC 参数、规划的当前时间线使用账号时区。日历日期运算改用 `formatCalendarDate`，不把 Date 字段当成需要换算的绝对时间。首页和规划默认的今天跟随账号午夜更新；手选历史日期保留。计时器时长和审计时间仍使用绝对时间，不能用时区偏移修改毫秒值。

`set_account_timezone` 与习惯 RPC 共用账号锁、版本号和请求 ID。null 预期版本只初始化缺失账号，不允许覆盖已有选择。单独改时区不生成目标规则；没有复制设置或批量迁移旧记录。新增前向迁移只增加 RPC 并调整节律未来日期验证，不移动已存任务、Daily 或习惯历史。

设置保存以服务器返回的版本立即更新，不等待统计读取。较旧读取不会覆盖新版本，取消的 React Query 请求不当成保存失败。实际读取失败保留已保存记录并给出重读入口及错误原因。切换账号后，上一账号迟到的写响应不进入新账号时钟。

## 验收

- 单测覆盖中国与美国同一瞬间的日期、DST 跳时、纯日期跨月与闰日、账号切换隔离、写失败与陈旧读取、保存后刷新失败。
- 浏览器用纽约设备时区选择中国账号时区，验证中国星期/日期、01:10 睡觉归日、直接编辑与焦点、刷新保留、首页与规划日期。
- UI 检查明暗四套主题、桌面与窄手机、WebKit、大字体、键盘操作和无横向溢出。
- SQL 测试覆盖初始化不覆盖、权限、版本冲突、幂等、时区独立保存与真实 RPC 的中国时间归属。按用户要求不启动本地数据库；SQL 执行结果以 CI 或实际远端回滚验证为准。

先部署 `202609120002_account_timezone.sql`，再更新 Web 和安装包。客户端回退时保留新增 RPC 和记录，0.1.5 可继续使用原有接口。
