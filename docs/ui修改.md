# 一、最重要的改动：今日日程的「预计 / 实际」必须拆成两列

参考图里「今日日程」表头目前是：

```text
时间 | 项目 | 任务 | 预计/实际
```

每一行里面又写：

```text
预计 40min
实际 —
```

或者：

```text
预计 1h30min
实际 56min
```

我不喜欢这种设计。

它实际上把两个完全不同的数据塞进了同一列，然后每一行都重复写“预计”“实际”，视觉噪音很大。

### 请直接改成独立两列：

```text
时间 | 项目 | 任务 | 预计 | 实际
```

例如：

```text
08:30        【工作】    邮件处理       40min      —
10:45        【课程】    统计课预习      1h         —
12:00–13:30  【课程】    领域论文       1h30min    56min
14:20        【AI研究】  跑 Demo        45min      —
15:10–16:10  【会议】    会议记录       1h         58min
17:00        【生活】    健身           1h         —
```

Checkbox 仍然保留在合理的位置。

---

## 这个改动的设计原则

### 1. 表头直接写：

```text
时间
项目
任务
预计
实际
```

不要再写：

```text
预计 / 实际
```

---

### 2. 每一行不要重复：

```text
预计
实际
```

这些文字。

因为列标题已经表达含义。

每行只需要显示：

```text
40min
—
```

或者：

```text
1h30min
56min
```

---

### 3. 「预计」与「实际」必须严格纵向对齐

我要的是一个真正稳定的桌面任务列表。

例如：

```text
预计        实际

40min       —
1h          —
1h30min     56min
45min       —
1h          58min
1h          —
```

不能每一行随着文字长度左右漂移。

优先使用合理的：

```text
CSS Grid
```

或者稳定列宽。

不要依赖大量随意 margin 来凑位置。

---

### 4. 不要把预计和实际做得太宽

这两列都是短数据。

合理给它们固定或者受控宽度即可。

应该把更多横向空间留给：

```text
任务名称
```

# 七、Daily 的宽度不能太窄

这是非常重要的约束。

```text

力
训
练
```

一个汉字一行的问题。

绝对不能再次出现。

正常情况下：

```text

背单词
发布周报
复盘错题
```

都必须横向显示。

如果窗口真的非常窄：

优先：

- 调整左右区域比例
- 减少次要信息
- 使用 ellipsis
- 把 Daily 移到下一行

也不要把中文任务名压成竖排。
