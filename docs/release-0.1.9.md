# Threadline 0.1.9

- 修复大数据量读取不完整、批注账号隔离和删除失败后的提前清理。旧版无归属批注可在「设置 → 数据与同步」主动导入，源数据保留。
- 任务编辑只提交实际修改字段；行内编辑保留打开时原值，失败不关闭输入。发生冲突后停止旧队列，并保留本次会话的最后草稿供用户对照、复制和重新编辑。
- 回收站恢复无损保留数据库删除时间的微秒精度，同时继续严格检查真正的并发变化。
- 工作站加入、移除、清空和排序保留其他设备的成员；写入后完整分页回读，超过 1000 个成员时不会因返回上限丢失显示。
- 修复 Daily 保存基准、非法耗时和输入法组合期间 Enter 提交；每日收尾拒绝移到过去日期。
- 后台刷新失败不再遮挡已打开的工作台；时区错误可在启动层重试，初始化请求支持真实超时和取消；修复登录展开与收起窗口的竞态以及固定地址 PWA 资源缓存。

## 部署顺序

先应用 `202609220001_issue_49_data_safety.sql` 并确认新 RPC 与权限，再合并部署 Web/PWA，最后推送 `v0.1.9` tag 触发 Windows Release。迁移增加或替换受账号权限约束的函数，保留旧接口，不重写历史账本或删除生产数据。旧客户端应升级；新版缺少迁移时不会退回不安全写入。

Windows Release 先检查 Preview/package-dir 一致性，再以生产配置构建 NSIS 安装包，发布安装器、blockmap 和 `latest.yml`；公开前回下载核对内容与校验值。

## 验证

修复提交 `4214aa3` 已通过全部四项 CI：411 项单元/组件测试、234 项 pgTAP、真实 PostgREST 与双浏览器云同步、321 项浏览器测试（另 10 项按既有条件跳过）、6 项 Preview 测试，以及真实 Electron 开发壳和打包 EXE smoke。

专项验证包括完整数据库返回 → 任务映射 → 恢复的微秒链路、仅差一微秒拒绝、冲突后排队停止、远端刷新后的行内旧草稿保护，以及 `max_rows=1000` 下 1001 成员加入和排序。

上述结果不替代 Windows 中文输入法、实际安装升级/卸载，以及真机 iPhone 输入和 PWA 恢复验收。完整修复与验收矩阵见 [Issue 49 记录](issue-49-regressions.md)。
